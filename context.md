# Project Context & Architecture Guide: rajkaranm.github.io

This document serves as the persistent architectural reference and operations manual for **rajkaranm.github.io**. It outlines the design system, compiler mechanics, content structure, and step-by-step instructions for adding posts or updating the site in the future.

---

## 1. Project Vision & Principles

The site is built on the **"Crafted Minimal"** philosophy—a hybrid of 1990s document-first efficiency (Dan Luu, Derek Sivers) and modern engineering notebook typography (Paco Coursey, Tom MacWright).

### Non-Negotiable Architectural Rules
1. **Zero Client-Side JavaScript:** 0 KB runtime, 0 trackers, 0 frameworks, 0 hydration overhead.
2. **Strict Payload Budget:** Under 30 KB total uncompressed payload (HTML + CSS combined) across every single page.
3. **Clean Directory Routing:** Every page lives in a directory `index.html` (e.g., `/tech/post-slug/`), ensuring clean trailing-slash URLs with zero file extensions visible to the user.
4. **Zero External Dependencies:** Built with a standalone Python 3 script (`build.py`) relying exclusively on standard library modules. No Node.js, no `npm install`, no `pip install`.
5. **Typographic Craft:** System-first typography with Google Fonts ([Inter](https://fonts.google.com/specimen/Inter) for reading text, [JetBrains Mono](https://fonts.google.com/specimen/JetBrains+Mono) for code, badges, and metadata). Generous `1.72` line-height on a `68ch` maximum reading measure.
6. **Dual-Theme Support:** Automatic dark and light mode switching via CSS variables and `prefers-color-scheme`.
7. **Configurable Domain:** A single variable `SITE_URL` at the top of `build.py` controls all canonical URLs, OpenGraph tags, and RSS feeds.

## 4. How to Update the Site (Step-by-Step)

### A. Adding a New Technical Article
1. Create a new markdown file: `content/tech/<your-slug>.md`.
2. Add YAML frontmatter at the very top:
   ```markdown
   ---
   title: "Your Post Title Here"
   date: "YYYY-MM-DD"
   summary: "1-2 sentence description explaining the key takeaway."
   ---

   Your content in standard markdown...

   ## Section Heading

   Inline `code` and fenced code blocks:

   ```python
   def example():
       return "clean"
   ```
   ```
3. Run `python3 build.py`.
4. The article will automatically be compiled to `tech/<your-slug>/index.html`, added to the `/tech/` archive, updated on the homepage, and injected into `/feed.xml`.

### B. Adding a New Personal Essay
1. Create a new markdown file: `content/personal/<your-slug>.md`.
2. Add YAML frontmatter:
   ```markdown
   ---
   title: "Your Essay Title"
   date: "YYYY-MM-DD"
   summary: "Brief 1-2 sentence overview of the thought or reflection."
   ---

   Your essay content...
   ```
3. Run `python3 build.py`.
4. The essay will be compiled to `personal/<your-slug>/index.html`, listed in `/personal/`, shown on the homepage, and added to `/feed.xml`.

### C. Updating the `/now` Page
1. Edit `content/now.md`.
2. Update the date and update what you are building, managing, reading, or researching.
3. Run `python3 build.py`.

### D. Updating Showcase Projects
1. Edit `content/projects.json`.
2. Add or modify an entry:
   ```json
   {
     "name": "System Name",
     "description": "Clear 1-2 sentence description of the system and its impact.",
     "url": "https://optional-link.com",
     "tags": ["Python", "FastAPI", "Redis", "RabbitMQ"]
   }
   ```
   *Note: If `url` is `""`, the system title will be rendered cleanly as text without an active link (ideal for proprietary systems).*
3. Run `python3 build.py`.

### E. Changing Your Domain Name in the Future
When you purchase or configure a new custom domain:
1. Open [`build.py`](build.py).
2. Update line 21:
   ```python
   SITE_URL = "https://your-new-domain.com"
   ```
3. Run `python3 build.py`.
   All canonical links, OpenGraph meta tags, and RSS `<link>` / `<guid>` entries will automatically recompile with the new domain.

### F. Updating Design or Styles
1. Edit `css/style.css`.
2. Keep the file compact and strictly under 8 KB.
3. Dark and light mode colors are controlled via CSS custom properties at the top of the file:
   * Light mode: `:root { --bg: #fafafa; --text: #171717; ... }`
   * Dark mode: `@media (prefers-color-scheme: dark) { :root { --bg: #121214; --text: #ededed; ... } }`

## 5. Local Testing & Verification

1. **Rebuild all pages:**
   ```bash
   python3 build.py
   ```
2. **Start the local preview server:**
   ```bash
   python3 -m http.server 4001
   ```
3. **Verify in browser:**
   * Homepage: [http://localhost:4001/](http://localhost:4001/)
   * Tech Archive: [http://localhost:4001/tech/](http://localhost:4001/tech/)
   * Personal Archive: [http://localhost:4001/personal/](http://localhost:4001/personal/)
   * Now Page: [http://localhost:4001/now/](http://localhost:4001/now/)
   * RSS Feed: [http://localhost:4001/feed.xml](http://localhost:4001/feed.xml)

## 6. Deployment Pipeline

Deploying to production on GitHub Pages is automated:
1. Stage and commit your changes:
   ```bash
   git add -A
   git commit -m "feat: publish new article on ..."
   ```
2. Push to the `master` branch:
   ```bash
   git push origin master
   ```
3. GitHub Actions ([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)) triggers on every push, runs `python3 build.py`, and publishes the static directory root directly to GitHub Pages.

## 7. Rules for AI Coding Assistants

When modifying this repository, any AI assistant MUST adhere to these constraints:
1. **Never introduce client-side JavaScript frameworks or runtime dependencies** (no React, Next.js, Vue, Svelte, Tailwind, or npm packages).
2. **Never break the 30 KB per page payload budget.**
3. **Never expose confidential information**, proprietary company names, private repository paths, or sensitive credentials. Keep project references high-level and focused on architectural patterns.
4. **Preserve clean trailing-slash directory routing** (`<slug>/index.html`).
5. **Always execute `python3 build.py`** after making content or template edits to ensure the generated static files match the source files.
